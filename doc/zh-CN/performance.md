# 性能与生命周期

[English](../manual/performance.md) · [文档目录](../README.md)

以下是代码中的调度目标，并非对当前游戏版本实测后的帧耗时保证。

## 需求框与筛选框

沿用的引擎会缓存物品属性、顾客接受结果和容器摘要。物品刷新、标签／类型变化、移动和容器窗口变化会令相关缓存失效。平时每 0.5 秒比较需求，重扫的最小间隔为 0.15 秒。

遍历覆盖店铺库存和打开的容器，关闭的容器优先使用摘要。引擎以 2.5 ms 为目标预算，未完成部分延后到后续帧；单次游戏调用及绘制仍可能超过目标。

呈现阶段会将匹配结果归一为实线完整框或内容物四角提示，框色按物品类型选择。矩形共用九宫格纹理，异形物品缓存独立掩码；粗细、圆角、底色继续影响几何。

## 全界面永久星标

`RiskStars` 独立注册原生物品视图，通过构造、刷新、标签／类型变化、移动和旋转事件更新。它不要求店铺单例、顾客或库存归属，且在需求框开关和空需求提前返回之前执行。

注册表对物品和 UI 使用弱引用，结合优先事件队列与轮询安全刷新。每帧以约 1.5 ms 为调度目标并限制处理数；普通视图每隔 0.25 秒可再次检查。大量物品排队时可能延后。星体与边缘共用两张点采样掩码，改变颜色和尺寸不为每件物品另建纹理。

赃物和违禁品分别判断，因此不会丢失“双属性红星”的状态。容器不汇总内容物的星标属性。

## 清理与诊断

离开店铺时释放需求引擎、框线和筛选窗口。单场景切换时释放星标 UI，但保留弱注册，以便新场景已创建的视图重绘；叠加场景不清空现有星标。物品模型回收后会清除孤立星标，停用模组会清理补丁、纹理和注册表。

日志前缀为 `[TypeDemandStars]`。超过 8 ms 的需求刷新会记录遍历和绘制耗时；这只是诊断阈值。错误颜色会记录警告并使用有效的回退颜色。

运行 `tests/run.sh` 可检查纯逻辑和替身集成场景；通过项及仍待实机验证的项目见 [VALIDATION.md](../../VALIDATION.md)。全店查询 API 的范围与调度方式另见[查询 API](query-api.md)。
